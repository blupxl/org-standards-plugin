Acme standards

Company standards for Claude Code, delivered at the point of work. Everything here runs on your machine.

Standards gateway (MCP) at http://localhost:5480/mcp. This page is its home page. Owners: design, platform, security Database UI: pgweb, in the Aspire dashboard Acme design system (stand-in): localhost:5500, the stylesheet the design standards require

The Aspire dashboard shows every resource, its logs, traces of each call, and the pgweb link. Its address, with a login token, is printed when the app starts: in Visual Studio's Output window, or in the terminal for dotnet run.

Connect Claude Code

  1. Keep this app running. You're already past this step if you can read this page.
  2. From the repository root, start Claude Code with the plugin loaded: 
    claude --plugin-dir ./plugins/my-company
    This loads the plugin for that session only. Nothing is installed or saved. To use it in your other projects, install it from this folder's local catalog instead (guide/install.md). Either way, everything stays on this machine.
  3. Check the connection inside Claude Code with /mcp: the server plugin:my-company:standards should be connected.

The plugin's skills (/my-company:standards, /my-company:assess) and reviewer agent are first drafts. The standards tools work on their own too, so you can also ask Claude for standards directly, as below.

Things to ask Claude

What standards are available? Use the standards tools.
I'm building a web API for xyz-public-app. Which standards apply for branding, resilience and performance?
I'm writing UI code for xyz-public-app. Which colors should I use, exactly?
Show me the caching example for xyz-public-app.
Assess this project against our standards and give me a report. (In another repository: /acme:assess, or /my-company:assess with --plugin-dir.)

The third prompt should make Claude call get_topic("Colors"): the main answer says the color tokens are available and how to fetch them. The fourth returns an example the product inherits from the general caching standard.

The tools

ToolReturns
list_standardsWhich fields (product, kind, concern, …) and values exist. Used to build a filter.
get_standardsThe standards to follow, as one Markdown document per request. Several requests in one call.
get_topicOne topic in full: examples, code, reference tables such as color tokens.

Filters are JSON: field → values, OR within a field, AND across fields. product is special: general topics come back as the base, and a product topic with the same name replaces the general one.

What Claude receives

# Standards
> **Scope:** product = xyz-public-app · kind = css, backend
> **Status:** complete
> **Sources:** design ✓, platform ✓
> **Precedence:** already resolved. A product-specific topic replaces the general topic with the same name, and says so.
> **Keywords:** MUST / MUST NOT = required · SHOULD = strong default · anything else is guidance.

## Colors
*design · XYZ Public App UI v1.0 · product: xyz-public-app · replaces the general topic (design v2.0)*

- MUST use the XYZ color tokens (`--xyz-primary`, `--xyz-surface`, `--xyz-danger`), not the Acme ones.
- MUST NOT use literal hex or rgb values.

Why: XYZ Public App is co-branded and has its own palette.

*More in this topic: Tokens. Fetch with `get_topic("Colors")` and the same filter.*

The header tells Claude how far to trust the document. If an owner is down, the status is partial; if a product name doesn't match, it's unresolved with a suggestion; an unknown field makes it invalid. Nothing is guessed.

Change the standards

Standards are Markdown files, one folder per owner: src/OrgStandards.Migrations/seed/<owner>/*.md. Edit a file and restart the app; the files are the source of truth, and the database is reloaded from them on every start. 

---
title: Web UI
version: 2.0
kind: [ui, css, styling]        # what the code is
concern: [branding]             # what it must achieve (optional); every other key is a tag too
---
## Colors                      ← a topic
- MUST use the Acme color tokens.

Why: one line on the reason.

### Tokens                     ← a detail, fetched on demand with get_topic
| Token | Value |

To add an owner, add its name to sources in src/OrgStandards.AppHost/Program.cs and create its folder under seed/. It gets a database, a server, and a pgweb bookmark; nothing else changes.
